┃ ▾ mem add ─┬ Add one or more Memories to the current or explicit Context.                                                                                                       ┃ 
┃            └ WHEN · Adding one or more facts, instructions, or notes directly to a Context.                                                                                     ┃ 
┃   FLOW      · Text or file -> Context Memories                                                                                                                                  ┃ 
┃   EXECUTION · DETERMINISTIC                                                                                                                                                     ┃ 
┃   EFFECT    · Changes the selected Context                                                                                                                                      ┃ 
┃   RANGE     · One exact target Context                                                                                                                                          ┃ 
┃   COPY OR LINK                                                                                                                                                                  ┃ 
┃   Text passed to Add is always stored literally as Memory content. Entering a Memory UID or Context name does not copy that object; it creates a new Memory containing that     ┃ 
┃   text.                                                                                                                                                                         ┃ 
┃   - INDEPENDENT WORK · Branch the containing Context and merge it later, or copy the Memory content and add it directly.                                                        ┃ 
┃   - EXACT MEMORY OR CONTEXT · Use mem reference to retain an immutable snapshot of one reviewed Source Memory or a direct/recursive Context scope. Run it bare interactively to ┃ 
┃     choose the unit.                                                                                                                                                            ┃ 
┃   - LIVE MEMORY · Use mem embed MEMORY --from SOURCE to follow the Source Memory's current content.                                                                             ┃ 
┃   - LIVE CONTEXT · Use mem embed. The parent stores only the Context identity; the child Memories remain in the child, although recursive operations may traverse them.         ┃ 
┃   FORM 1 · mem add "[memory_content]" (add one Memory to the current Context)                                                                                                   ┃ 
┃   FORM 2 · mem add (open the interactive multi-Memory editor)                                                                                                                   ┃ 
┃   FORM 3 · mem add --memory "[memory_content]" --memory "[memory_content]" (add an explicit batch)                                                                              ┃ 
┃   FORM 4 · mem add --input [file] (add one Memory per non-empty line)                                                                                                           ┃ 
┃   FORM 5 · mem add --paste (paste one or more Memories)                                                                                                                         ┃ 
┃   FORM 6 · mem add "[memory_content]" --context [context] (add to an explicit Context)                                                                                          ┃ 
┃   FORM 7 · mem add --input [file] --context [context] (batch-add to an explicit Context)                                                                                        ┃ 
┃   FORM 8 · mem add --paste --context [context] (paste into an explicit Context)                                                                                                 ┃ 
┃ ▸ mem atomize ─┬ Immediately atomize the current Context into independently reviewable Memories and save the full analysis for Review.                                          ┃ 
┃                └ WHEN · Untangling requirements or claims that were written together so each can be reviewed and revised independently.                                         ┃ 
┃ ▸ mem audit ─┬ Run Duplicate, Ambiguity, and Conflict checks plus optional Rule Conformance, then review the combined saved result.                                             ┃ 
┃              └ WHEN · Performing a combined quality review before revising a Context.                                                                                           ┃ 
┃ ▸ mem branch ─┬ Copy a Context or subtree into a new branch and switch to it.                                                                                                   ┃ 
┃               └ WHEN · Editing a Context or subtree independently while preserving the original.                                                                                ┃ 
┃ ▸ mem check- ──────┬ Check one Context or saved Ground Examples against explicit Rules or condition propositions and report conformance issues.                                 ┃ 
┃     conformance    └ WHEN · Verifying whether existing Memories or Examples satisfy stated Rules or condition propositions.                                                     ┃ 
┃ ▸ mem checkout ─┬ Switch Contexts using Git-style syntax; with -b, create and switch to a new Context branch.                                                                   ┃ 
┃                 └ WHEN · Using a Git-like workflow to switch or create a branch.                                                                                                ┃ 
┃ ▸ mem checkpoint ─┬ Save the current Context as a manual recovery point for Diff or Revert.                                                                                     ┃ 
┃                   └ WHEN · Creating a recovery point before risky work.                                                                                                         ┃ 
┃ ▸ mem chunk ─┬ Mechanically split all splittable direct Memories in one Context, or one selected Memory, at configured sentence, clause, structural, literal, or size           ┃ 
┃              │ boundaries.                                                                                                                                                      ┃ 
┃              └ WHEN · One or more direct Memories already have clear sentence or structural boundaries that should become separate Memories.                                    ┃ 
┃ ▸ mem clear ─┬ Immediately remove all direct items from the current or explicit Context; Undo can restore them.                                                                 ┃ 
┃              └ WHEN · Emptying a Context while retaining the Context itself.                                                                                                    ┃ 
┃ ▸ mem compare ─┬ Compare Memories in two Contexts and report what they share, what differs, and what appears only on one side.                                                  ┃ 
┃                └ WHEN · Comparing two Contexts as a whole to understand where they align and differ.                                                                            ┃v
