┌ CORE CONCEPTS ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┐^
│ MEMORY      An atomic unit of information stored in a Context.                                                                                                                  │ 
│ CONTEXT     A named workspace that organizes Memories and other Contexts.                                                                                                       │ 
│ PROFILE     An ownership and storage boundary for Contexts.                                                                                                                     │ 
│ GRANT       A permission relationship that can be given or received, selectively allowing someone without direct ownership to read or query a Context and its Memories, or run  │ 
│             permitted operations on them, while the Grant remains valid.                                                                                                        │ 
│ SESSION     A saved record of an analysis or review workflow that can be reopened and continued; it does not itself mean Context changes were applied.                          │ 
│ CHECKPOINT  A recoverable history boundary created for each applied operation and recorded per affected Context.                                                                │

┃ ▸ mem contexts   Browse ordinary local Contexts and readable cross-Profile Context views without switching; print the catalog outside a terminal.                               ┃

┃ ▸ mem show       Show a Memory, reference, embedded Context, or the direct contents of a current/explicit Context.                                                              ┃ 
┃ ▸ mem switch     Enter the interactive Context picker, or switch to an explicit Context.                                                                                        ┃ 
┃ ▸ mem checkout   Switch Contexts using Git-style syntax; with -b, create and switch to a new Context branch.                                                                    ┃ 
┃ ▸ mem init       Edit a suggested name, or create an explicitly named Context, and switch to it; --parents ensures its hierarchy.                                               ┃ 
┃ ▸ mem branch     Choose a local Source range and exact fresh target when unnamed, or branch the current Context or subtree to an explicit new name.                             ┃ 
┃ ▸ mem import     Import a clean-baseline Profile, Context tree, or Memory by value while preserving resource identity.                                                          ┃ 
┃ ▸ mem embed      Choose a Child, target, and direct-item insertion gap interactively, or add one Context at an explicit before/after position while the Child retains its       ┃ 
┃                  identity and ownership.                                                                                                                                        ┃
