┌ DETERMINISTIC CONTENT CHANGES ──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┐ 
│ NO LLM · Apply explicit inputs and reviewed choices through deterministic program logic to change content.                                                                      │ 
│ ▸ mem edit            ─┬ Directly replace the content of one or more Memories selected by UID or prefix.                                                                        │ 
│                        └ WHEN · Directly correcting or replacing the content of specific existing Memories.                                                                     │ 
│ ▸ mem replace         ─┬ Preview and replace every literal or explicit regular-expression match in ordinary local Memories.                                                     │ 
│                        └ WHEN · Correcting, renaming, or redacting exact text throughout a known local Context scope.                                                           │ 
│ ▸ mem chunk           ─┬ Mechanically split all splittable direct Memories in one Context, or one selected Memory, at configured sentence, clause, structural, literal, or size │ 
│                        │ boundaries.                                                                                                                                            │ 
│                        └ WHEN · A Memory already has clear text boundaries that should become separate Memories.                                                                │ 
│ ▸ mem delete (remove) ─┬ Select a Context or direct item to delete, or name it by locator, name, or UID.                                                                        │ 
│                        └ WHEN · Removing a specific Context or item that is no longer needed.                                                                                   │ 
│ ▸ mem clear           ─┬ Remove all direct items from the current or explicit Context after confirmation.                                                                       │ 
│                        └ WHEN · Emptying a Context while retaining the Context itself.                                                                                          │ 
│ ▸ mem merge           ─┬ Add Source-only items to a selected Target, leave exact matches unchanged, and choose Source or Target for stored-item conflicts.                      │ 
│                        └ WHEN · Appending Source-only items or bringing a copied or branched Context into a selected Target Context without semantic synthesis.                 │ 
│ ▸ mem dedup           ─┬ Remove byte-identical duplicates (dup) immediately, retaining the first existing UID for each exact-content group.                                     │ 
│                        └ WHEN · Removing byte-identical direct Memories while preserving the first existing UID.                                                                │

┏ SEMANTIC TRANSFORMATIONS ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓ 
┃ LLM-BASED · Uses LLM semantic analysis to restructure, derive, translate, curate, or reconcile content.                                                                         ┃ 
┃ ▸ mem atomize   ─┬ Immediately atomize the current Context into independently reviewable Memories and save the full analysis for Review.                                        ┃ 
┃                  └ WHEN · Untangling requirements or claims that were written together so each can be reviewed and revised independently.                                       ┃ 
┃ ▸ mem distill   ─┬ Derive higher-level Rules or condition propositions from Case or Example propositions in a bounded Context, optionally guided by a Goal.                     ┃ 
┃                  └ WHEN · Inferring more general Rules or condition propositions from several concrete cases or examples.                                                       ┃ 
┃ ▸ mem elaborate ─┬ Expand an abstract Goal, Rule, or condition into multiple more specific candidate propositions.                                                              ┃ 
┃                  └ WHEN · Generating several more concrete candidate Rules or Cases from an abstract concept or condition.                                                      ┃ 
┃ ▸ mem translate ─┬ Generate and save a reusable translated view of one Context or Memory while preserving the original content.                                                 ┃ 
┃                  └ WHEN · Reading or reusing Memory content in another language without replacing the original.                                                                 ┃ 
┃ ▸ mem forget    ─┬ Review keep/edit/delete decisions for one instruction, then apply the accepted batch.                                                                        ┃ 
┃                  └ WHEN · Removing or rewriting Memories according to a natural-language instruction whose meaning must be interpreted.                                         ┃ 
┃ ▸ mem resolve   ─┬ Propose and verify minimum changes that make one bounded direct-Memory Context frame Fit YES.                                                                ┃ 
┃                  └ WHEN · Deciding how to repair semantic conflicts or ambiguities within a bounded Context frame.                                                              ┃ 
┃ ▸ mem dedun     ─┬ Find and resolve semantic redundancies (dun), retaining one unchanged existing Memory in each reviewed group.                                                ┃ 
┃                  └ WHEN · Removing semantic redundancy while preserving one exact existing Memory and its UID in each reviewed group.                                           ┃ 
┃ ▾ mem update    ─┬ Update Memories in the Target Context from Memories in the Source Context, asking the user to review and choose when needed.                                 ┃ 
┃                  └ WHEN · Updating an existing Context using newly verified Memories.                                                                                           ┃ 
┃   FLOW      · Source Context -> Target Context                                                                                                                                  ┃ 
┃   EXECUTION · SEMANTIC                                                                                                                                                          ┃ 
┃   EFFECT    · Changes only the local Target after Apply                                                                                                                         ┃ 
┃   RANGE     · Each endpoint exact or readable descendants                                                                                                                       ┃ 
┃   UPDATE VS. MELD                                                                                                                                                               ┃ 
┃   Update is revision-oriented: it treats a Source as verified change evidence and semantically patches an existing Target. Meld is merge-oriented: it semantically combines two ┃ 
┃   inputs while reconciling their relationships and conflicts, either into an existing Baseline or a new Result.                                                                 ┃
