# Task 1 wiki update and audience-intent preview

> **DESIGNER PREVIEW · NOT APPLIED · ACCESS ENFORCEMENT: NONE**
>
> 이 표의 열람 대상은 의도된 공개 범위를 검토하기 위한 sidecar다.
> 현재 `Memory`는 `uid`와 `content`만 저장하며, `mem ls`, `mem show`,
> `impact`, `update`는 역할별로 ordinary Memory를 걸러내지 않는다.
> 따라서 아래 표시를 실제 접근 통제로 해석하거나 Memory 본문에
> `[교직원 전용]` 같은 접두어로 넣으면 안 된다. 현재 실제로 내용을
> 숨기는 경로는 Context 전체를 감추는 query-only prototype뿐이며,
> 그것도 사용자 역할을 인증하는 ACL은 아니다.

## 표시 규칙

- 아래 표의 한 행은 여러 원자 Memory를 한눈에 검토하기 위한
  change-set 요약일 수 있다. 이 요약문을 Memory 본문으로 복사하지
  않고, 실제 후보와 diff는 원자 단위 fixture/TSV를 기준으로 한다.
- `EDIT`: 기존 위키 Memory를 바꾼다.
- `ADD`: 기존 위키에 없는 독립 Memory를 추가한다.
- `NOOP`: 기존 위키가 이미 같은 의미를 담고 있어 보존한다.
- `MERGE`: 중복되거나 복합적인 원문을 한 번만 반영한다.
- `BASELINE`: 공사로 생긴 변화가 아니라 위키에 원래 있어야 할
  안정적인 배경정보다.
- `BLOCKED`: 목적지는 알지만 필요한 사실이 비어 있어 아직 적용할
  수 없다.
- `전체`가 `✓`이면 방문객·학생·교직원·공사/건물관계자 열도 모두
  `✓`로 표시한다. 이는 중복이 아니라 요청된 전체 역할 확인표다.
- `적용 대상`은 문장이 누구에게 적용되는지를 뜻한다. 오른쪽 다섯
  열은 누가 그 문장을 볼 수 있어야 하는지에 관한 **의도**다.

공개 상태, 자격 기반 출입, 교직원 운영정보를 서로 다른 페이지로
분리하는 것이다.
